1 · Architecture Overview

Browser (React) Server (Next.js Route) Anthropic API ──────────────── ────────────────────── ───────────── useChat hook ──POST──▶ route.ts ──▶ Claude (manages state) ◀──stream── streamText() ◀── (streams tokens)

This is a streaming chat app. Instead of waiting for Claude to finish writing its entire reply before showing anything, the server streams tokens back to the browser one chunk at a time — the same way you see Claude "type" in real time on claude.ai.

There are exactly two files that contain all of the application logic:

FileRole
app/api/chat/route.tsReceives messages from the browser, calls Claude, streams the response back
app/page.tsxRenders the chat UI, captures user input, sends it to the route

2 · The Three Package Roles

"@ai-sdk/anthropic": "^3.0.85"   ← Model provider  (server-side only)
"@ai-sdk/react":     "^3.0.210"  ← React hooks     (client-side only)
"ai":                "^6.0.208"  ← Core engine     (both sides)

Each package has one job and one job only. Understanding this boundary prevents the most common class of import errors.

PackageWhat it containsWhat it does NOT contain
@ai-sdk/anthropic The anthropic() model factory. Knows how to authenticate and format requests for Anthropic's API. React hooks. Any UI logic. Anything browser-related.
@ai-sdk/react The useChat() hook. Manages conversation state, streaming, and sending messages. Model providers. API credentials. Any server logic.
ai streamText, convertToModelMessages, and all the streaming plumbing that connects the two sides. —
Rule Never import useChat from @ai-sdk/anthropic. That package has no idea React exists. Hooks always come from @ai-sdk/react.

3 · The API Route

File: app/api/chat/route.ts

import { streamText, convertToModelMessages } from 'ai';
import { anthropic } from '@ai-sdk/anthropic';

const model = anthropic('claude-sonnet-4-6');

export async function POST(req: Request) {
  const { messages } = await req.json();

  const result = streamText({
    model: model,
    system: systemPrompt,
    messages: await convertToModelMessages(messages),
  });

  return result.toUIMessageStreamResponse();
}

Line-by-line breakdown

import { streamText, convertToModelMessages } from 'ai'

  • streamText — the main function for making a streaming LLM call. You will use this in every AI app that needs real-time output.
  • convertToModelMessages — translates the frontend's UIMessage[] format into the ModelMessage[] format that streamText expects. This conversion is required in ai v6 because the client and server use different message schemas.

import { anthropic } from '@ai-sdk/anthropic'

anthropic is a factory function. Call it with a model ID string and it returns a model object the SDK knows how to call. The key benefit: you can swap providers with a one-line change.

// Anthropic
import { anthropic } from '@ai-sdk/anthropic';
const model = anthropic('claude-sonnet-4-6');

// OpenAI — same pattern, different import
import { openai } from '@ai-sdk/openai';
const model = openai('gpt-4o');

// Everything else in the route stays identical.

export async function POST(req: Request)

Next.js App Router convention. A file at app/api/chat/route.ts that exports a function named POST automatically becomes the endpoint POST /api/chat. No configuration needed. The function name must match the HTTP method exactly.

const { messages } = await req.json()

Parses the JSON body sent by useChat. In ai v6, the body is { id, messages, trigger, messageId }. We only need messages.

await convertToModelMessages(messages)

This is required because the client and server use different message formats in v6:

FormatUsed byShape
UIMessage[]Browser / useChat{ id, role, parts: [{ type, text }] }
ModelMessage[]Server / streamText{ role, content: string | array }
Critical convertToModelMessages is an async function. Always await it. Without await, you pass a Promise object to streamText instead of an array, causing a crash.

result.toUIMessageStreamResponse()

Converts the streamText result into an HTTP streaming response that useChat knows how to consume. In ai v6 this replaced the old toDataStreamResponse().

The system prompt

The system field gives Claude its persona and instructions. It is always separate from messages — it is never shown to the user and never appears in the conversation history. This separation is a strict convention across all LLM APIs.

4 · The Frontend

File: app/page.tsx

'use client';

import { useState } from 'react';
import { useChat } from '@ai-sdk/react';

export default function Chat() {
  const { messages, sendMessage, status } = useChat();
  const [input, setInput] = useState('');
  const isLoading = status !== 'ready';

  function handleSubmit(e: React.FormEvent) {
    e.preventDefault();
    if (!input.trim() || isLoading) return;
    sendMessage({ text: input });
    setInput('');
  }
  // ...
}

Line-by-line breakdown

'use client'

Next.js App Router runs components on the server by default. This directive tells Next.js this component uses browser APIs — React state, event handlers — and must run in the browser. Any file using useState, useEffect, or any hook requires this at the top.

useChat()

The core hook from @ai-sdk/react. It manages the entire chat lifecycle. By default it posts to /api/chat, matching the route file exactly.

PropertyTypeWhat it does
messagesUIMessage[]The full conversation history. Re-renders the component as new tokens arrive during streaming.
sendMessagefunctionSends a message to /api/chat and begins streaming the response.
status'ready' | 'submitted' | 'streaming' | 'error'Current state of the connection.

const isLoading = status !== 'ready'

In older SDK versions this was a boolean isLoading returned directly by the hook. In v3 it became a status string with four possible values. status !== 'ready' covers both 'submitted' (request sent, waiting for first token) and 'streaming' (tokens arriving).

sendMessage({ text: input })

The v3 API for submitting a message. The argument is { text: string }. Internally, the hook converts this into a UIMessage with parts: [{ type: 'text', text: '...' }] and sends the full conversation history to the API route.

const [input, setInput] = useState('')

In older SDK versions useChat owned the input state and returned input and handleInputChange. In v3 it no longer does. You manage input yourself with useState — the same as any controlled form field in React.

Rendering messages

{messages.map((message) => (
  <div key={message.id}>
    {(message.parts ?? [{ type: 'text', text: message.content ?? '' }]).map((part, i) =>
      part.type === 'text'
        ? part.text.split('**').map((chunk, j) =>
            j % 2 === 1
              ? <strong key={`${i}-${j}`}>{chunk}</strong>
              : chunk
          )
        : null
    )}
  </div>
))}
ElementWhy it exists
message.idReact requires a stable key when mapping lists. The SDK generates a unique ID for every message.
message.partsIn ai v6, messages are structured content blocks, not flat strings. Each part has a type field ('text', 'file', 'tool-call', etc.).
?? fallbackNullish coalescing — if parts is undefined, fall back to wrapping the old content string. Guards against edge-case messages.
split('**') logicMinimal inline markdown parser for bold text. Every odd-indexed chunk after splitting on ** was between two markers. A real app would use react-markdown.

5 · The Data Flow End-to-End

Here is exactly what happens when you type a message and hit Send:

  1. User types in the input field → setInput updates React state → the field re-renders with the new value.
  2. User clicks Send → handleSubmit fires → sendMessage({ text: "Hello" }) is called.
  3. useChat builds a UIMessage: { id: "abc", role: "user", parts: [{ type: "text", text: "Hello" }] } → appends it to messages instantly → sets status to 'submitted' → POST /api/chat with the full message history.
  4. Route receives the POST → req.json() extracts messages → await convertToModelMessages() converts format → streamText() calls Anthropic with stream: true.
  5. Anthropic streams tokens back → streamText forwards them through toUIMessageStreamResponse() as SSE (Server-Sent Events) chunks.
  6. useChat receives the stream → updates the assistant message in messages in real time → status changes to 'streaming' → component re-renders with each token (text appears live).
  7. Stream ends → status returns to 'ready' → isLoading becomes false → input field re-enables.

6 · Key Patterns You Will Reuse Everywhere

These six patterns from this codebase appear in virtually every AI application you will build. Learn to recognize them on sight.

Pattern 1 — Provider + streamText (server)

This is the foundation of every streaming AI API route. Swap the provider import and model string to change models. Everything else stays identical.

import { streamText, convertToModelMessages } from 'ai';
import { anthropic } from '@ai-sdk/anthropic';

const result = streamText({
  model: anthropic('claude-sonnet-4-6'),
  system: 'You are a helpful assistant.',
  messages: await convertToModelMessages(messages),
});

return result.toUIMessageStreamResponse();

Pattern 2 — useChat hook (client)

Your standard starting point for any chat interface. You will add options as apps grow complex, but the destructured values stay the same.

const { messages, sendMessage, status } = useChat();
// With options:
const { messages, sendMessage, status } = useChat({
  api: '/api/custom-endpoint',
  headers: { Authorization: `Bearer ${token}` },
});

Pattern 3 — Controlled input with local state

Always pair useChat with your own useState for the text field, since the hook no longer owns input state.

const [input, setInput] = useState('');

function handleSubmit(e) {
  e.preventDefault();
  sendMessage({ text: input });
  setInput(''); // always clear after sending
}

Pattern 4 — UIMessage parts rendering

Every time you render a message, iterate parts and filter by type. As you build more advanced apps (tool calls, file attachments, reasoning traces), you add more type cases here.

{message.parts.map((part, i) => {
  if (part.type === 'text')      return <span key={i}>{part.text}</span>;
  if (part.type === 'tool-call') return <ToolCallCard key={i} call={part} />;
  return null;
})}

Pattern 5 — System prompt separation

The system prompt always goes in the system field — never inside messages. It is Claude's private instruction set and is never visible to the user.

streamText({
  system: 'You are a race engineer teaching AI concepts...',
  messages: conversationHistory, // system prompt never appears here
});

Pattern 6 — Streaming response method

Always return toUIMessageStreamResponse() from your route. This is the method that converts the streamText result into a proper HTTP streaming response.

// ai v6 — current
return result.toUIMessageStreamResponse();

// ai v3–v5 — you will see this in older tutorials; it no longer exists
return result.toDataStreamResponse(); // ← broken in v6
Tip When you search for AI SDK tutorials online, check the date. Tutorials before mid-2025 show the old API (handleSubmit, isLoading, toDataStreamResponse, etc.) which will all fail on the current SDK versions.

7 · Debugging Post-Mortem

This app hit 6 distinct errors during setup. Every one was caused by breaking changes in ai v6 and @ai-sdk/react v3 — versions new enough that most tutorials and AI coding assistants do not know about them. Here is each error, its root cause, and the fix.

ERROR 1 useChat imported from the wrong package 
Module not found: Can't resolve 'useChat' from '@ai-sdk/anthropic'

Root cause: The original code imported useChat from @ai-sdk/anthropic. That package is only a model provider — it has no React code. This is a common confusion because both packages share the @ai-sdk/ namespace.

✓ Fix
// Before
import { useChat } from '@ai-sdk/anthropic';

// After
import { useChat } from '@ai-sdk/react';

Rule: @ai-sdk/anthropic = model factory only. @ai-sdk/react = hooks only.

ERROR 2 input.trim() crashes — input is undefined 
TypeError: Cannot read properties of undefined (reading 'trim')
    at Chat (app/page.tsx:59)

Root cause: In the old SDK (ai v3), useChat returned { input, handleInputChange, handleSubmit, isLoading } — the hook owned the input field. In @ai-sdk/react v3 (new), the hook no longer manages input state at all. input is simply not returned, so it is undefined.

✓ Fix
// Before — hook owned the input
const { messages, input, handleInputChange, handleSubmit, isLoading } = useChat();

// After — you own the input
const { messages, sendMessage, status } = useChat();
const [input, setInput] = useState('');
const isLoading = status !== 'ready';
ERROR 3 message.parts is undefined 
TypeError: Cannot read properties of undefined (reading 'map')
    at message.parts.map (app/page.tsx:39)

Root cause: Two problems at once. First, the rendering code used message.content (a flat string) but ai v6 replaced this with a parts array. Second, sendMessage({ role: 'user', content: input }) is the old API — the v3 hook did not recognize that shape and stored the object as-is, without building the parts array.

✓ Fix
// Before — old sendMessage API, no parts array built
sendMessage({ role: 'user', content: input });

// After — correct v6 API; hook builds parts: [{ type: 'text', text: input }]
sendMessage({ text: input });
// Before — rendered flat string
{message.content}

// After — renders structured parts
{(message.parts ?? []).map((part, i) =>
  part.type === 'text' ? part.text : null
)}
ERROR 4 toDataStreamResponse is not a function 
TypeError: result.toDataStreamResponse is not a function
    at POST (app/api/chat/route.ts:283)

Root cause: In ai v3–v5, the streaming result had a method called toDataStreamResponse(). In ai v6, this was renamed to toUIMessageStreamResponse() as part of the new UIMessage architecture. The old method no longer exists on the result object.

✓ Fix
// Before
return result.toDataStreamResponse();

// After
return result.toUIMessageStreamResponse();
ERROR 5 messages.some is not a function 
TypeError: messages.some is not a function

Root cause: convertToModelMessages is declared as an async function. Without await, calling it returns a Promise object instead of an array. streamText received a Promise and crashed when it tried to call .some() on it — a method that does not exist on Promise.

This is a subtle async bug. The code compiles without TypeScript errors but fails at runtime. The tell-tale sign: any method that belongs on an array (.some, .map, .filter) throwing "is not a function" usually means you are calling an async function without await.

✓ Fix
// Before — passes a Promise to streamText
messages: convertToModelMessages(messages),

// After — awaits the conversion, passes a real array
messages: await convertToModelMessages(messages),

Rule: Any time a function is declared async and you intend to use its return value, you must await it.

ERROR 6 404 from Anthropic API — model not found 
AI_APICallError: statusCode: 404
"type": "not_found_error"
"message": "model: claude-3-5-sonnet-20240620"

Root cause: The model ID claude-3-5-sonnet-20240620 was deprecated by Anthropic. The API returns a 404 for any model ID that no longer exists. This is not a code bug — it is a version management issue. Model IDs are not permanent.

✓ Fix
// Before — deprecated model
const model = anthropic('claude-3-5-sonnet-20240620');

// After — current production model (as of 2026)
const model = anthropic('claude-sonnet-4-6');

Rule: When an app stops working with a 404 from the Anthropic API and the error message contains a model name, the model has been retired. Check the Anthropic documentation for current model IDs.
